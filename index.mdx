RepoKernel is the coordination layer between your AI coding agents and your Git repository. Every task runs in its own worktree, locked to declared file paths, sequenced by dependencies, and gated by review before anything reaches `main`. No daemon, no cloud, no database — your repo is the source of truth.

## Why RepoKernel

Running one AI coding agent is easy. Running three in parallel against the same repo is where things fall apart — state conflicts, double-dispatch, scope creep, and zero visibility. RepoKernel fixes each of these at the filesystem layer.

<CardGroup cols={2}>
  <Card title="Isolated Worktrees" icon="code-branch">
    Each task runs in its own `git worktree`. Your `main` branch stays clean until review and merge.
  </Card>
  <Card title="Atomic Sprint Claims" icon="lock">
    Two parallel `rk run` invocations cannot both pick up the same sprint — claims are filesystem-atomic.
  </Card>
  <Card title="Scope Enforcement" icon="shield">
    `allowed_paths` in sprint frontmatter flags out-of-scope edits at review time before merge.
  </Card>
  <Card title="Review Gates" icon="check">
    Configured checks must pass and a review verdict must be recorded before anything reaches `main`.
  </Card>
  <Card title="Merge-Safe Registry" icon="merge">
    A custom Git merge driver unions agent state by ID — no JSON conflict markers between parallel agents.
  </Card>
  <Card title="Crash Recovery" icon="rotate">
    Failed or runaway agents leave a resumable run, not a corrupted repository.
  </Card>
</CardGroup>
